# AI-Based Adaptive Fan Speed Control Using Temperature Prediction

An ECE capstone project demonstrating time-series temperature prediction and predictive fan-speed recommendations. The included demo dataset is **synthetic/simulated**; collect real sensor readings before reporting real-world performance.

## Features

- Generates a reproducible temperature time-series for a demo.
- Builds lag and rolling-average features from recent readings.
- Trains a Random Forest regression model to predict the next sample's temperature.
- Reports MAE, RMSE and R² on a chronological hold-out set.
- Compares predictive fan control with a threshold-based baseline.
- Provides an interactive Streamlit dashboard and exportable recommendation CSV.
- Includes an ESP32 PWM output sketch and safety notes.

## Quick start (Windows / Linux / macOS)

Python 3.10 or newer is recommended.

```bash
# 1. Open this project directory
cd adaptive-fan-control

# 2. Create and activate a virtual environment (optional but recommended)
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate

# 3. Install dependencies
python -m pip install -r requirements.txt

# 4. Generate demo data, train model, and print evaluation metrics
python src/train_model.py

# 5. Start dashboard
streamlit run app.py
```

Open the local URL printed by Streamlit (normally `http://localhost:8501`).

## How it works

1. Temperature readings are ordered in time.
2. Features include current temperature, the previous two readings, 5- and 15-sample rolling means, ambient temperature, estimated heat load, and previous fan speed.
3. A Random Forest regressor predicts the next sample (the synthetic dataset treats one sample as one minute).
4. The predicted temperature is converted to a fan command using a configurable cooling range. The command changes by at most 20 percentage points per update to avoid abrupt speed changes.
5. The same current temperature is passed to a simple threshold baseline for comparison.

## Dataset format for real sensors

CSV columns required by the training script:

- `temperature_c`: measured temperature in °C
- `ambient_c`: ambient temperature in °C
- `heat_load`: estimated load (project-defined numeric scale, suggested 0–1.2)
- `fan_speed_pct`: fan command/measurement from 0 to 100

An optional `timestamp` column is retained in the data but is not used as a feature. Collect readings at a consistent interval, calibrate the sensor, document the environment, and include a timestamp. Replace `data/temperature_readings.csv` with your measured CSV and run `python -m src.train_model` only if you package `src` as a module; the most straightforward supported command is `python src/train_model.py` from the project root.

**Important:** avoid random train/test splitting for time-series data. This project uses an earlier-time training segment and a later-time test segment to reduce leakage. Synthetic test metrics only describe this simulated dataset and must not be presented as measured hardware accuracy.

## Hardware setup (suggested)

- ESP32 development board
- DS18B20 or another temperature sensor with a suitable interface
- Low-voltage DC fan with a compatible PWM/control input
- Appropriately rated MOSFET/driver, external fan power supply, wiring, and protection components

The included sketch accepts integer fan-speed commands from 0 to 100 over Serial and outputs PWM. It is a **hardware output example, not a complete sensor-to-AI deployment**: connect and validate the sensor, then implement communication from the Python controller to the ESP32 (USB serial or a secured local network). The dashboard currently displays a recommendation but does not send commands to hardware.

### Safety

- Never power a fan directly from an ESP32 GPIO.
- Verify fan voltage/current, PWM frequency/polarity, and driver ratings.
- Use a common ground where required by the driver design; follow the fan and board documentation.
- Test first with a low-voltage load and a current-limited supply.
- Add a sensor-failure fallback (for example, a conservative safe fan command) before unattended operation.
- Do not use this student prototype for medical, industrial, or other safety-critical cooling.

## Suggested project evaluation

Record the following in the final report after you collect actual data:

- MAE (°C), RMSE (°C), and R² for next-step prediction.
- Temperature peak and settling time for both control policies.
- Average fan speed / energy proxy (e.g., average PWM duty; this is not true power unless measured).
- Overshoot, number of abrupt changes, and response to a simulated heat-load step.

Do not claim that predictive control is better unless the measured experiments support it. Compare both methods under the same initial conditions and heat load.
